# 学習支援Webアプリ 要件定義レビュー

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |

| 目的 | 基本設計へ進む前に、要件定義の矛盾、不足、未決事項の対応状況を管理する |

## 2. 総評

要件定義書は、中心課題を学習計画の作成、進捗把握、計画修正に整理し、MVP 1からMVP 3までの段階リリースとして再構成した。

初回レビューで指摘したWBSの入力・親タスク設定・削除、プロジェクト状態・アーカイブ、過去時点EVM、認証、一覧表示、非機能要件の主要論点は要件として確定した。質問管理と教材内容へのAI回答は中心課題との関係を再評価し、最終MVPから将来拡張へ移した。技術スタック、AIサービス、タイムアウト値、未保存変更確認など、実装方式に依存する事項は基本設計へ移管した。

## 3. 対応状況の定義

| 対応状況 | 意味 |
| --- | --- |
| 解消済み | 要件定義書へルールを反映し、基本設計の前提として確定した |
| 基本設計へ移管 | 要件ではなく、方式設計として基本設計で決定する |
| 将来拡張へ移管 | 最終MVPから除外し、将来追加する際に改めて要件定義する |
| 継続課題 | 要件として未確定であり、基本設計前に判断が必要 |

## 5. ブラッシュアップで確定した主要事項

### 5.1 MVP構成

- 開発と受入確認をMVP 1からMVP 3へ分割する。
- MVP 1で個人用の学習計画・実績管理表を完成させ、MVP 2で計画との差を可視化する。
- MVP 3では教材入力、OCR、AI学習計画生成、保存前の直接編集・再生成により、AIで学習管理表を作成できる状態を目指す。
- 質問管理と教材内容へのAI回答は将来拡張として扱う。

### 5.2 プロジェクトとWBS

- プロジェクト状態とアーカイブを別に管理する。
- 親タスクは見出しとして扱い、計画値、実績値、進捗率、学習記録を持たない。
- タスクは親タスク配下または親なしで管理でき、プロジェクト集計とEVMの対象とする。
- WBSの削除、自動並び替え、親タスク設定の制約を定義した。

### 5.3 画面構成と学習記録

- ユーザーは原則として現在取り組む1つの学習プロジェクトを選択し、プロジェクト内でWBS、学習記録、進捗分析を利用する方針とした。AI学習計画生成は新規プロジェクト作成時の独立した作成ルートとして扱う。
- ナビゲーションはプロジェクト未選択時の共通機能と、プロジェクト選択後のプロジェクト内機能で表示対象を切り替える方針とした。
- ログイン後の初期画面はプロジェクト一覧とし、ユーザー単位の連続学習日数と総学習時間をプロジェクト一覧上部に表示する。
- 独立したダッシュボード画面とプロジェクト横断の学習記録一覧はMVP対象外とした。
- 学習記録はプロジェクト内機能として扱い、プロジェクト内の記録一覧、登録、編集、削除を行えるようにした。
- 連続学習日数はユーザー単位で算出し、計算基準日はJST当日、判定対象日は登録日時ではなくユーザーが入力した学習日とした。
- JST当日に学習記録がない場合でも、JST前日に学習記録があれば前日までの連続学習日数を表示する。
- プロジェクト概要では、プロジェクト単位の学習時間を「プロジェクト学習時間」として扱う。

### 5.4 EVMと履歴

- EVM指標の基準日はJST当日に固定し、過去日を基準日として指定する機能は提供しない。
- 進捗履歴、WBS計画履歴、プロジェクト期間履歴はMVP 1から保持するが、履歴一覧は提供しない。
- 日別EVは、JST各日終了時点の進捗率履歴と、現在有効なタスク予定工数に基づいて算出する。
- 予定工数、予定日、プロジェクト期間を変更した場合、日別EVとバーンダウンは現在の計画値で再計算し、過去時点の計画値を用いた日別EVの再現は提供しない。
- WBS計画履歴とプロジェクト期間履歴は、MVP 2のEVM・バーンダウン計算には使用せず、将来拡張または変更追跡のために保持する。
- PVの日付境界、JST当日の時刻境界、表示時の丸め規則を定義した。
- EVM指標のうちBAC、PV、EV、AC、SV、CVは0値表示を許可し、SVとCVは符号付き時間数として表示する。
- SPIはPVが0の場合、CPIはACが0の場合に「-」と表示する。SPIは1.0未満の場合のみ「遅れ」、CPIは1.0未満の場合のみ「超過」と表示し、1.0以上の場合は状態ラベルを表示しない。
- バーンダウンは前倒し、予定どおり、遅れの閾値判定を行わず、理想残と実績残の差分日数を直接表示する。BACが0または計算対象タスクが存在しない場合は「-」と表示する。
- EVM指標はカード形式で表示し、EVM指標の時系列推移グラフは提供しない。進捗推移はバーンダウンチャートで確認する。

### 5.5 AI支援の対象

- AI支援は、学習計画案の作成（保存前の直接編集・削除・再生成を含む）を最終MVPの対象とする。AI作成は新規プロジェクト作成時の独立した作成ルートに限定する。
- 質問管理、回答メモ、教材内容へのAI回答、AI回答履歴は最終MVPの対象外とし、将来拡張へ移した。
- 学習中の気づきや補足は、最終MVPでは学習記録の任意メモで扱う。

### 5.6 PC Webと将来のFlutterスマホアプリ

- このリポジトリではPC用Web版を実装対象とする。
- Flutterスマホアプリは別リポジトリ `study-pm-mobile` で作成する想定とする。
- 将来のFlutterスマホアプリからも利用できるよう、認証、データ、入力制約、EVM計算、AI学習計画の送信範囲、API仕様は共通化を前提にする。
- AI学習計画生成は、PC Web版では画像選択または貼り付けテキストからOCR結果を修正して生成する。

## 7. 継続課題

要件定義として基本設計前に判断が必要な継続課題はない。

基本設計では、要件を満たすために次の点を重点的に検討する。

1. WBSの親タスク設定と履歴保持を両立するデータ構造
2. JST各日終了時点の日別EVとバーンダウン実績線を算出する集計方式
3. アーカイブ済みデータを更新不可にするAPI制御
4. AI学習計画生成で送信する情報をユーザーが確認できる画面導線
5. 一覧検索と集計を想定件数で実用的に動作させるインデックス

## 8. 次工程

1. 基本設計書の構成を決定する。
2. 画面一覧、画面遷移図、画面項目定義を作成する。
3. ER図、テーブル定義、履歴データの保持方式を作成する。
4. REST API一覧、主要API仕様を作成する。
5. EVM、タスク集計、日別EV、バーンダウンなどの業務ロジックを設計する。
6. 設計確認用のUIモックを作成する。
