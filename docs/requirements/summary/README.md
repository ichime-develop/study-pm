## 3. 背景

本アプリは、Java、データベース、ITアーキテクト、プロジェクト管理を実践的に学ぶための開発題材として作成する。

独学では、教材や目標を決めても、学習範囲の分解、予定と実績の比較、遅延の把握、計画の見直しが別々になりやすい。

本アプリは、学習目標を「学習プロジェクト」として管理し、エンジニアが学習しながらプロジェクト管理の考え方も身につけられるツールを目指す。

開発者の学習目的として、要件定義、設計、実装、レビューを段階的に進める仕様駆動開発の考え方を取り入れる。
ただし、仕様駆動開発支援そのものは最終MVPのアプリ機能には含めない。

本アプリは、全プロジェクト横断の学習履歴管理よりも、ユーザーが現在取り組んでいる1つの学習プロジェクトを深く管理する体験を重視する。
ユーザーはプロジェクト一覧から対象プロジェクトを選択し、プロジェクト内でWBS、進捗分析、学習記録を切り替えて利用する。
AI学習計画生成は、新規プロジェクト作成時の独立した作成ルートとして提供する。
画面ナビゲーションは、プロジェクト外の共通機能と、選択中プロジェクト内の機能を分けて表示する。

## 4. アプリの目的

1. 学習目標をプロジェクト単位で明確にする。
2. 学習内容をWBSとして分解し、実行可能なタスクにする。
3. 予定工数、学習時間、進捗率を記録し、計画との差を把握する。
4. EVMとバーンダウンチャートにより、遅延や工数超過を早期に発見する。
5. AI学習計画生成により、新規プロジェクト作成時の計画作成の負担を軽減する。

## 5. 想定ユーザー

- Java、SQL、クラウド系などの資格試験を学習するエンジニア
- 独学の計画と進捗を定量的に管理したい人

## 6. 利用形態

- 各ユーザーは自分の学習情報のみを管理する。
- チーム学習、講師によるレビュー、他ユーザーへの公開は対象外とする。
- PC Webでの利用を主対象とする。
- 本リポジトリではPC用Web版、共通設計、将来のFlutterスマホアプリ向けAPI仕様を扱う。
- Flutterスマホアプリは別リポジトリ `study-pm-mobile` で作成する想定とする。
- 将来のFlutterスマホアプリでも、原則としてPC Web版と同じ主要機能を提供できるようにAPIと業務ルールを共通化する。

## 7. 最終MVPの概要

最終MVPでは、学習計画を手動またはAI支援で登録し、日々の学習実績を入力して、進捗を可視化する基本サイクルを完成させる。

```text
学習プロジェクト作成（手動またはAIと作成を選択）
  -> [手動ルート] WBSを作成し、学習予定を設定する
  -> [AIルート]  概要または教材目次とこだわり条件から検証済みWBS下書きを作成し、編集してWBSを保存する
  -> 学習記録の登録
  -> 必要に応じて学習記録メモの追加
  -> 進捗率の更新
  -> プロジェクト内で状況確認
```

## 8. 段階リリース

| リリース | 目的 | 対象機能 |
| --- | --- | --- |
| MVP 1 | 個人用の学習計画・実績管理表として使える | 認証、プロジェクト、WBS、学習記録、プロジェクト一覧ホーム |
| MVP 2 | 計画との差を可視化できる | 履歴を用いた進捗分析、EVM、バーンダウン、遅延表示 |
| MVP 3 | AIで学習管理表を作成できる | 教材目次OCR、概要・目次とこだわり条件からの検証済みWBS下書き生成、保存前編集、条件・教材を変えた再生成 |

MVP 1は、ユーザーが自分の学習プロジェクトを作成し、WBS形式で学習予定を分解し、日々の学習実績と進捗率を記録して、予定工数、実績工数、進捗率を確認できる状態を完成条件とする。

MVP 1では、MVP 2以降の日別EVとバーンダウン実績線の計算に利用するため、進捗履歴を保存する。計画履歴とプロジェクト期間履歴は将来拡張または変更追跡のために保存する。ただし、履歴一覧を表示する機能は提供しない。

画面モックはMVP 1だけに閉じず、最終MVP全体の機能配置を見据えて作成する。実装と受入確認は段階リリースごとに切り分ける。

## 10. 要件詳細化の優先順位

機能ごとの要件定義は、利用頻度、中心業務への影響、後続設計への依存度を考慮し、次の順序で詳細化する。

| 優先順位 | 機能領域 | 詳細化の主な観点 |
| --- | --- | --- |
| 1 | プロジェクト管理 | 作成、編集、一覧、概要、状態、削除、プロジェクト概要画面 |
| 2 | WBS管理 | 親タスク・タスク、予定日、予定工数、並び順、削除制約、集計 |
| 3 | 学習記録 | 学習日、対象タスク、学習時間、任意メモ、実績工数再集計 |
| 4 | 進捗履歴・EVM・バーンダウン | 履歴保存、基準日、PV/EV/AC、指標表示、計画不整合 |
| 5 | 教材入力・OCR・AI学習計画生成 | 学習目標、学習期間、概要、教材目次、画像、OCR、こだわり条件、検証済みWBS下書き、保存前編集 |
| 6 | プロジェクト一覧ホーム | プロジェクト選択、進行中プロジェクト、連続学習日数、総学習時間 |
| 7 | 認証・アカウント | 登録、ログイン、ログアウト、所有者制御 |
| 8 | 管理者向けコスト確認 | AI利用量、概算コスト、ユーザー別・期間別集計 |

## 11. 主要な設計前提

- 日本語UIを主対象とする。
- タイムゾーンはユーザー設定を導入するまで日本標準時（JST）を基準とする。
- 日付は日単位で管理し、最終MVPではタスクの開始時刻・終了時刻を管理しない。
- EVMは学習時間をコストとして扱う。
- PVは休日を除外せず、全暦日へ均等配分する。
- ログイン後の初期画面はプロジェクト一覧とし、独立したダッシュボード画面はMVP対象外とする。
- プロジェクト選択後の作業スペースでは、概要、WBS、進捗分析、学習記録をプロジェクト内機能として自然に切り替えられる情報設計を行う。
- ナビゲーションは、プロジェクト未選択時はプロジェクト一覧、プロジェクト作成、AI学習計画生成などの共通機能を中心に表示し、プロジェクト選択後は概要、WBS、進捗分析、学習記録などのプロジェクト内機能を中心に表示する。

## 12. 次工程

1. 優先順位に沿って機能領域ごとの要件を詳細化する。
2. 最終MVP全体を見据えたPC Web版の画面モックを作成する。
3. 画面モックを確認し、MVP 1で実装する範囲と後続MVPへ送る範囲を切り分ける。
4. 基本設計書の構成を決定する。
5. 画面一覧、画面遷移、主要画面のワイヤーフレームを整理する。
6. エンティティ関連図とテーブル定義を作成する。
7. REST API一覧と主要なAPI仕様を作成する。
8. EVM、タスク集計、日別EV、バーンダウンなどの業務ロジックを設計する。
