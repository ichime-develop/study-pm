# 非機能要件

## 14. 非機能要件

### 14.1 性能

| ID | 要件 |
| --- | --- |
| NFR-PERF-01 | 通常の画面表示は、一般的な利用状況で3秒以内を目標とする。 |
| NFR-PERF-02 | 一覧検索は、1ユーザーあたりプロジェクト100件、WBSタスク10,000件を想定して実用的な速度で動作する。 |
| NFR-PERF-03 | 集計処理に必要な検索条件には適切なインデックスを設定する。 |

### 14.2 セキュリティ

| ID | 要件 |
| --- | --- |
| NFR-SEC-01 | 認証済みユーザーのみアプリの主要機能を利用できる。 |
| NFR-SEC-02 | ユーザーは他ユーザーのデータを閲覧・更新できない。 |
| NFR-SEC-03 | パスワードは安全なハッシュ方式で保存する。 |
| NFR-SEC-04 | 入力値検証をサーバー側でも行う。 |
| NFR-SEC-05 | SQLインジェクション、XSS、CSRFへの対策を行う。 |
| NFR-SEC-06 | 秘密情報や認証情報をログに出力しない。 |
| NFR-SEC-07 | AIサービスへ送信する情報に、不要な個人情報や秘密情報を含めない。 |
| NFR-SEC-08 | AIサービスへ送信する内容は、要件で定義した学習目標、学習期間、学習内容の概要、教材情報、学習可能時間、制約条件の範囲に限定する。 |
| NFR-SEC-09 | 教材目次画像はOCRサービスにだけ送信し、WBS生成を行うAIサービスへ送信しない。 |
| NFR-SEC-10 | 認証情報、メールアドレス、表示名、内部UUID、学習記録、他プロジェクトの情報をOCR・AIサービスへ送信しない。 |
| NFR-SEC-11 | 教材目次画像、OCR結果、入力プロンプトの全文をアプリケーションログへ出力しない。 |
| NFR-SEC-12 | OCR・AIサービスの認証情報はサーバー側の秘密情報として管理し、リポジトリ、PC Web、APIレスポンスへ含めない。 |
| NFR-SEC-13 | OCR修正結果、生成条件、WBS下書きと入力元対応は再開・評価に必要な設定期間だけ保持し、期限到達後は自動削除する。教材目次画像は永続保存しない。 |

### 14.3 可用性・バックアップ

| ID | 要件 |
| --- | --- |
| NFR-AVL-01 | 個人学習用途として、計画停止を除き継続利用できることを目標とする。 |
| NFR-AVL-02 | データベースは1日1回バックアップし、直近7日分を保持できる構成とする。 |
| NFR-AVL-03 | 障害時に原因を調査できるログを記録する。 |
| NFR-AVL-04 | OCRまたはAIサービスが利用できない場合も、手動でのプロジェクト作成と既存のMVP 1・MVP 2機能を利用できる。 |

### 14.4 保守性・拡張性

| ID | 要件 |
| --- | --- |
| NFR-MNT-01 | PC Webフロントエンドとバックエンドの責務を分離する。 |
| NFR-MNT-02 | 将来のFlutterスマホアプリからも利用できるREST APIとしてバックエンド機能を提供する。 |
| NFR-MNT-03 | Google認証を追加できるよう、ユーザー認証方式を拡張可能にする。 |
| NFR-MNT-04 | 画像解析、WBS生成の処理を業務ロジックから分離する。 |
| NFR-MNT-05 | 主要な業務ロジックには自動テストを作成する。 |
| NFR-MNT-06 | DB変更はマイグレーションツールで管理する。 |
| NFR-MNT-07 | OCRサービス、AIモデル、プロンプト、構造化出力スキーマ、サーバー生成戦略を個別に変更・識別できる構成とする。 |
| NFR-MNT-08 | 通常のCIでは外部OCR・AIサービスを実行せず、スタブ、固定レスポンス、契約テストで検証する。実サービスを使う確認は手動または明示的な検証として分離する。 |

### 14.5 ユーザビリティ

| ID | 要件 |
| --- | --- |
| NFR-USE-01 | PC Webは最新Google Chromeを正式対応ブラウザとする。 |
| NFR-USE-02 | PC WebはPC画面幅での利用を正式対応範囲とする。 |
| NFR-USE-03 | 学習記録は少ない操作で登録できるようにする。 |
| NFR-USE-04 | 進捗遅延、工数超過、計画不整合を視覚的に区別する。 |
| NFR-USE-05 | 入力エラー時は、原因と修正方法をユーザーに表示する。 |
| NFR-USE-06 | AIの生成結果を確定情報として扱わず、入力内容とWBS下書きを段階的に確認・修正できる。 |
| NFR-USE-07 | AI処理中は処理状態、停止操作、失敗理由、再試行方法を表示し、二重実行を防止する。 |

### 14.6 コスト管理

| ID | 要件 |
| --- | --- |
| NFR-COST-01 | Google Cloud Vision、OpenAI API、AWS、サーバーなど有料サービスを利用する場合、管理者が発生金額または利用料金の見込みをいつでも確認できる構成とする。 |
| NFR-COST-02 | 有料サービスの利用量、課金状況、予算超過リスクを管理者が把握できるよう、サービス側の請求ダッシュボード、予算アラート、利用量ログなどを活用する。 |
| NFR-COST-03 | OCR画像数、AI処理回数、モデル、入出力トークン数、処理時間、再試行回数を、入力本文を含めずに記録し、品質と費用の比較に利用できる。 |
| NFR-COST-04 | AI処理の停止は外部サービスの処理や料金発生を必ず止めるものではないことを運用上の前提とする。 |
