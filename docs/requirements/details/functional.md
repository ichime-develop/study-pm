# 機能要件

## 9. 機能要件

### 9.1 ユーザー管理

| ID | 要件 |
| --- | --- |
| USR-01 | ユーザーはメールアドレスとパスワードでアカウントを登録できる。 |
| USR-02 | ユーザーは登録済みの認証情報でログインできる。 |
| USR-03 | ユーザーはログアウトできる。 |
| USR-04 | ユーザーは自分が登録したデータのみ閲覧・更新できる。 |
| USR-05 | パスワードは平文で保存しない。 |
| USR-06 | メールアドレスは大文字小文字を区別せず一意とする。 |
| USR-07 | パスワードは8文字以上とし、英大文字、英小文字、数字をそれぞれ1文字以上含める。 |
| USR-08 | 認証に失敗した場合、メールアドレスまたはパスワードのどちらが誤っているかを特定できないメッセージを表示する。 |

### 9.2 学習プロジェクト管理

| ID | 要件 |
| --- | --- |
| PRJ-01 | ユーザーは学習プロジェクトを作成できる。 |
| PRJ-02 | 学習プロジェクトには、名称、概要、開始日、目標終了日を設定できる。 |
| PRJ-03 | ユーザーは学習プロジェクトの内容を編集できる。 |
| PRJ-04 | ユーザーは学習プロジェクトを一覧表示できる。 |
| PRJ-05 | 一覧では、状態、期間、進捗率、予定工数、実績工数を確認できる。 |
| PRJ-06 | ユーザーは学習プロジェクトを未着手、進行中、完了の状態で管理できる。 |
| PRJ-07 | ユーザーは学習プロジェクトの詳細を表示できる。 |
| PRJ-08 | 学習プロジェクトの予定工数、実績工数、進捗率は、親タスクを除くタスクから自動集計される。 |
| PRJ-09 | ユーザーは不要な学習プロジェクトを削除できる。 |
| PRJ-10 | 学習プロジェクトを削除する前に、システムは削除対象と復元できないことを確認する。 |
| PRJ-11 | 削除した学習プロジェクトは復元できない。 |
| PRJ-12 | 学習プロジェクトを削除した場合、対象プロジェクト配下のWBS、学習記録、履歴も削除対象とする。 |
| PRJ-13 | システムはプロジェクト開始日と目標終了日の変更履歴を保存する。 |
| PRJ-14 | 学習プロジェクト作成時、名称、開始日、目標終了日は必須とする。 |
| PRJ-15 | 学習プロジェクト作成時の初期状態は未着手とする。 |
| PRJ-16 | ユーザーはプロジェクト一覧をキーワード、状態で絞り込める。 |
| PRJ-17 | ユーザーはプロジェクト一覧を更新日時、開始日、目標終了日、進捗率で並び替えできる。 |
| PRJ-18 | プロジェクト概要では、プロジェクト基本情報、主要指標、警告、未完了タスクを確認できる。 |
| PRJ-19 | ユーザーはプロジェクト選択後、各画面で共通のプロジェクト内ナビゲーションから、概要、WBS、学習記録、進捗分析を切り替えられる。 |
| PRJ-20 | ユーザーはプロジェクト状態を未着手、進行中、完了の範囲で変更できる。 |
| PRJ-21 | 完了条件を満たさないプロジェクトを完了に変更しようとした場合、システムは変更を拒否し、未完了タスクの存在を表示する。 |
| PRJ-22 | プロジェクト開始日または目標終了日を変更した場合、システムは変更後の期間に基づいて計画情報の整合性を再判定する。 |
| PRJ-23 | 削除した学習プロジェクトはプロジェクト一覧、プロジェクト概要、プロジェクト内機能の表示対象から除外する。 |
| PRJ-24 | 学習プロジェクトを削除した場合、対象プロジェクトの学習記録はユーザー単位の総学習時間と連続学習日数の算出対象から除外する。 |
| PRJ-25 | ユーザーは学習プロジェクトの削除操作を確認画面でキャンセルできる。 |
| PRJ-26 | システムはプロジェクトの作成日時、更新日時を保持する。 |
| PRJ-27 | プロジェクト概要では、WBSタスクが未登録の場合に、プロジェクト基本情報、WBSタスクが0件であること、予定工数・進捗率が未算出であること、WBS作成へ進む導線を表示する。WBSタスクが未登録の場合、予定工数や進捗率を通常の数値として誤表示しない。 |
| PRJ-28 | プロジェクト概要では、プロジェクトの学習状況を判断する主要情報を初期表示で確認できる。 |
| PRJ-29 | ログイン後の初期画面はプロジェクト一覧とする。 |
| PRJ-30 | 独立したダッシュボード画面はMVP対象外とする。 |
| PRJ-31 | ユーザーはプロジェクト新規作成時に、手動で作成またはAIと作成のいずれかを選択できる。 |
| PRJ-32 | 手動作成フローでは、AI作成への切り替え操作やAI機能の説明を表示しない。 |
| PRJ-33 | 手動でプロジェクトを作成した場合、保存後にプロジェクト概要画面へ遷移する。 |

### 9.3 WBS管理

| ID | 要件 |
| --- | --- |
| WBS-01 | ユーザーは学習プロジェクト内に親タスクとタスクを作成できる。 |
| WBS-02 | 親タスクには名称、説明を設定できる。 |
| WBS-03 | タスクには名称、説明、親タスク、開始予定日、終了予定日、予定工数、進捗率を設定できる。 |
| WBS-04 | ユーザーはWBSを親タスクとタスクの最大2階層で管理でき、タスク配下にタスクを作成できない。 |
| WBS-05 | ユーザーはWBSタスクを編集できる。 |
| WBS-06 | WBSタスクは同じ階層内で開始予定日、終了予定日、登録日時に基づいて自動並び替えされる。 |
| WBS-07 | ユーザーはタスクの親タスクを設定または変更できる。 |
| WBS-08 | ユーザーは関連データが存在しないWBSタスクを削除できる。 |
| WBS-09 | ユーザーはタスクの進捗率を0%から100%まで10%単位で更新できる。 |
| WBS-10 | 進捗率が100%になったタスクは完了状態として扱う。 |
| WBS-11 | 完了状態を解除する場合、進捗率を100%未満へ変更できる。 |
| WBS-12 | ユーザーはタスクごとの実績工数を、学習記録から集計された値として確認できる。 |
| WBS-13 | 親タスクは予定日、予定工数、実績工数、進捗率、学習記録を持たず、プロジェクト集計、EVM、バーンダウンの計算対象に含めない。 |
| WBS-14 | ユーザーはタスクの遅延状態を確認できる。 |
| WBS-15 | システムはタスク作成時に0%の進捗履歴を保存し、保存前後で進捗率の値が異なる場合のみ、変更後の値を履歴として保存する。同一値を保存した場合は履歴を追加しない。 |
| WBS-16 | システムは開始予定日、終了予定日、予定工数、親タスク設定の変更履歴を保存する。 |
| WBS-17 | ユーザーは親タスクをWBSの最上位に追加できる。 |
| WBS-18 | ユーザーは選択中の親タスク配下、選択中タスクと同じ親タスク配下、または親なしの最上位にタスクを追加できる。 |
| WBS-19 | ユーザーが開始予定日または終了予定日を変更した場合、保存後のWBS表示順は自動並び替え結果に従う。 |
| WBS-20 | 親タスクを削除する場合、削除前に確認を行い、配下のタスクも削除対象とする。 |
| WBS-21 | 学習記録が存在するタスクは削除できない。 |
| WBS-22 | 学習記録が存在するタスクも、同一プロジェクト内での名称、説明、予定日、予定工数、進捗率、親タスクを変更できる。 |
| WBS-23 | タスクを別プロジェクトへ移動することはできない。 |
| WBS-24 | WBSタスクが0件の状態でも、WBS・ガント画面を表示し、親タスクまたは親なしタスクの追加を開始できる。 |
| WBS-25 | WBSタスクが0件のプロジェクトでは、学習記録機能を利用できない。学習記録タブを無効にして遷移を禁止する。 |

### 9.4 学習記録管理

| ID | 要件 |
| --- | --- |
| LOG-01 | ユーザーはタスクに対して学習記録を登録できる。 |
| LOG-02 | 学習記録には、学習日、対象タスク、学習時間、任意メモを設定できる。 |
| LOG-03 | 学習時間は0.25時間以上の値とし、0.25時間単位で入力できる。 |
| LOG-04 | ユーザーは学習記録の学習日を手動で入力できる。 |
| LOG-05 | 未来日の学習記録は登録できない。 |
| LOG-06 | 学習記録の追加、変更、削除に応じて、タスクとプロジェクトの実績工数が再集計される。 |
| LOG-07 | ユーザーは登録済み学習記録の学習日、対象タスク、学習時間、任意メモを編集できる。 |
| LOG-08 | ユーザーは登録済み学習記録を削除できる。 |
| LOG-09 | ユーザーは過去日の学習記録を期限なく編集・削除できる。 |
| LOG-12 | ユーザーは完了済みタスクにも学習記録を登録できる。 |
| LOG-13 | 親タスクには学習記録を登録できない。 |
| LOG-14 | ユーザーは登録した学習記録を確認できる。 |
| LOG-15 | 同じタスクに複数の学習記録を登録でき、既存の学習記録は上書きしない。 |
| LOG-16 | ユーザーはプロジェクト内の学習記録を、対象タスクを指定せずに確認、編集、削除できる。 |
| LOG-17 | プロジェクト横断の学習記録一覧はMVP対象外とする。 |
| LOG-18 | 過去の学習日を持つ学習記録を後から登録、変更、削除した場合、連続学習日数と総学習時間の算出へ反映する。 |
| LOG-19 | ユーザーはWBSで選択中のタスクを対象として、WBSの作業文脈を維持したまま学習記録を登録できる。 |

### 9.5 進捗・EVM管理

| ID | 要件 |
| --- | --- |
| EVM-01 | システムはプロジェクト単位でBAC、PV、EV、ACを計算する。 |
| EVM-02 | システムはプロジェクト単位でSV、CV、SPI、CPIを計算する。 |
| EVM-03 | EVM指標の基準日はJST当日に固定し、ユーザーが基準日を指定または変更する機能は提供しない。 |
| EVM-04 | ユーザーはEVM指標をカード形式で確認でき、EVM指標の時系列推移グラフは提供しない。 |
| EVM-05 | システムは工数超過、進捗遅延、指標未算出を区別して表示する。 |
| EVM-06 | システムはプロジェクト単位で理想線と実績線を含むバーンダウンチャートを表示する。 |
| EVM-07 | バーンダウンチャートは日ごとの残予定工数を表示する。 |
| EVM-08 | 将来日付のPVは、タスクの予定期間に基づいて算出できる。 |
| EVM-09 | システムはJSTの各日終了時点までに保存された最新の進捗率と、現在有効なタスク予定工数を用いて、日ごとのEVを算出する。 |
| EVM-09A | 過去日を基準日として指定し、EVM指標を算出または表示する機能は提供しない。 |
| EVM-10 | バーンダウンの実績線は、BACから日ごとのEVを差し引いた残予定工数として表示する。 |
| EVM-11 | 計画情報に不整合が存在する場合、計画不整合として警告する。 |
| EVM-12 | システムはバーンダウンチャートにおいて、基準日時点の差分日数を表示し、前倒し、予定どおり、遅れの閾値判定は行わない。 |
| EVM-13 | システムはSPI、CPI、バーンダウンの算出不可条件を定義し、算出不可と0値の指標表示を区別する。 |
| EVM-14 | 予定工数、予定日、プロジェクト期間を変更した場合、システムは日別EVおよびバーンダウンチャートを現在の計画値に基づいて再計算する。 |
| EVM-15 | 進捗分析画面ではEVM学習を目的としてSPIおよびCPIの数値を主表示とし、SPIが1.0未満の場合のみ「遅れ」、CPIが1.0未満の場合のみ「超過」を表示する。 |

### 9.6 AI学習計画生成

| ID | 要件 |
| --- | --- |
| PLN-01 | AI学習計画生成の入力は、学習目標、学習期間、学習内容の概要、目次テキスト、教材目次画像、こだわり条件とする。ユーザーは概要だけを入力する方法と、目次テキストまたは教材目次画像を利用する方法を選択できる。 |
| PLN-02 | PC Webでは、フォーム形式の入力画面から、目次テキストの直接入力と教材目次画像のアップロードを利用できる。 |
| PLN-03 | 教材目次画像のOCR処理はサーバー側で扱い、将来のFlutterスマホアプリから送信される画像にも再利用できるようにする。 |
| PLN-04 | ユーザーはOCR結果または貼り付けた目次テキストをAI送信前に確認・修正できる。 |
| PLN-05 | ユーザーは学習目標、学習開始日・目標終了日を必須入力とし、こだわり条件（1日の学習可能時間、学習できない曜日、日程補足、重点・軽め・除外範囲）を任意で設定して学習項目候補とWBS下書きを段階的に生成できる。 |
| PLN-06 | WBS下書きには、学習プロジェクト候補、親タスクとLEAFタスク、予定日、予定工数を含める。WBS下書きを生成する前に、入力内容から学習項目候補を生成する。 |
| PLN-07 | WBS下書きはプロジェクトとWBSへ直接保存せず、ユーザーが確認して変換を実行した場合だけ保存する。 |
| PLN-08 | AI学習計画生成に失敗した場合、入力済みの教材名、OCR結果、生成条件を失わず、失敗理由を表示し、再試行できる。 |
| PLN-09 | AI学習計画生成時に、ユーザーの認証情報をAIサービスへ送信しない。 |
| PLN-10 | AI学習計画生成中は実行停止操作を表示し、生成中の二重実行を防止する。 |
| PLN-11 | 教材目次画像は複数アップロードできる。 |
| PLN-12 | 対応画像形式はjpg、jpeg、png、webpとする。 |
| PLN-13 | 教材目次画像は最大10枚、1画像あたり最大10MB、合計最大50MBまでとする。PC Webおよび将来のクライアントは画像数と合計サイズをOCR送信前に検証し、サーバーは1画像あたりのサイズと、1つの生成依頼へ保存できるOCR入力元が最大10件であることを検証する。 |
| PLN-14 | 複数画像のOCR結果は、ユーザーが指定した画像順に結合する。 |
| PLN-15 | ユーザーはアップロードした教材目次画像の並び順を変更できる。 |
| PLN-16 | ユーザーはWBS下書きの生成後・変換前に、各タスクのタスク名・タスク種別（親タスク／タスク）・親タスク・予定開始日・予定終了日・予定工数を直接編集できる。 |
| PLN-17 | ユーザーはWBS下書きの生成後・変換前に、タスクを削除できる。親タスクを削除した場合は確認後に配下タスクも削除する。 |
| PLN-18 | ユーザーはWBS下書きの生成後・変換前に、入力条件画面または学習項目候補確認画面へ戻って内容を変更し、必要な段階から再生成できる。 |
| PLN-19 | ユーザーはAI学習計画生成時に、重点的に学習したい範囲、軽く確認したい範囲、除外したい範囲を自然文で指定できる。 |
| PLN-20 | ユーザーは複数の教材、問題集、公式ドキュメントの目次やメモを1つのAI学習計画生成依頼に含められる。 |
| PLN-21 | ユーザーはAIが抽出または補足した学習項目候補を、WBS下書きの生成前に確認・編集・追加・削除できる。 |
| PLN-22 | 学習項目候補には、入力由来またはAI補足の由来と、重点・通常・軽め・除外の優先度を保持する。 |
| PLN-23 | ユーザーは学習項目候補の一覧を一括して確認済みにできる。確認後に候補一覧を編集した場合、確認済み状態を解除し、再確認を必要とする。 |
| PLN-24 | システムは、現在の候補一覧が確認済みであり、除外されていない学習項目候補が1件以上ある場合だけ、WBS下書きの生成を開始できる。 |
| PLN-25 | WBS下書きの生成には、確認済みの学習項目候補、候補ごとの優先度、確認済みの数量条件、学習目標、学習期間、学習可能時間、学習できない曜日、日程補足を利用する。自然文の日程補足と確認済み数量条件が競合する場合は確認済み数量条件を正本とする。確認済み候補の生成後は、OCR結果や目次テキストの全文をWBS生成AIへ再送しない。 |
| PLN-26 | AIが生成した内容はプロジェクトやWBSへ直接保存せず、サーバーで必須項目、最大2階層、予定工数の0.25時間単位、予定日、学習項目候補との対応を検証した下書きとして保存する。 |
| PLN-27 | 学習項目候補と入力元、学習項目候補とWBS下書きタスクの対応は、下書きの確認と生成品質評価に必要な期間だけ保持する。プロジェクトへの変換後は、通常のプロジェクトとWBSとして扱い、この対応関係を業務データとして保持しない。 |
| PLN-28 | システムは、開始日が終了日より後、利用可能な学習時間が0、除外されていない学習項目候補が0件など、生成前に判定できる入力矛盾を検出し、生成を開始せず理由と修正方法を表示する。 |
| PLN-29 | WBS下書きの生成後、システムは予定工数と学習可能時間の不整合を判定し、警告と、解除すべき条件を最大3件の単一条件変更案として表示する。組み合わせ最適化は行わない。 |
| PLN-30 | システムは通常生成と期限優先のどちらでも、1日24時間を超える計画を生成しない。ユーザーが期限内の完了を優先した場合は、除外されていない確認済み候補と予定工数を維持し、24時間以内であれば希望する1日あたり学習時間を超えるWBS下書きを警告付きで作成できる。 |
| PLN-31 | 学習項目候補の抽出とWBS下書きの生成は、それぞれ独立した非同期処理として状態、期限、失敗理由、再試行を管理する。 |
| PLN-32 | ユーザーはAI処理の実行中に停止を要求できる。停止はベストエフォートとし、外部サービスの処理完了や料金発生を必ず防止できるものではない。停止要求後に返った結果は下書きへ保存しない。 |
| PLN-33 | AI処理の一時的な通信失敗やレート制限は自動再試行の対象とする。構造化出力の検証失敗は、各処理につき1回だけ自動再生成し、それでも失敗した場合はユーザーが再試行できる状態にする。 |
| PLN-34 | システムはユーザーごとのAI生成回数を日単位で制限できる。上限到達時は生成を開始せず、利用可能になる時期を表示する。具体的な上限値は運用設定とする。 |
| PLN-35 | AI作成方法の選択画面には、利用する外部サービス、送信する情報、送信しない情報、各サービスのデータ利用方針への導線を常時表示する。ユーザーが条件入力へ進む操作を、表示内容を確認したものとして扱い、同意状態を管理する専用画面・API・DB項目は新設しない。 |
| PLN-36 | 教材目次画像はOCR処理のためGoogle Cloud Visionへだけ送信し、OpenAIへは送信しない。OpenAIへ送信するのは、ユーザーが修正したOCR結果、直接入力したテキスト、確認済み学習項目候補および生成条件に限定する。 |
| PLN-37 | 教材目次画像は処理中の一時データとして扱い、永続保存しない。OCR結果、修正後テキスト、生成条件、学習項目候補、WBS下書きは、再開・再試行・確認に必要な範囲で保持できる。 |
| PLN-38 | AI入力が文字数上限を超える場合、システムは自動的に切り捨てず、超過した項目と修正方法を表示する。 |
| PLN-39 | 「全300ページを1日10ページ」のような自然文の数量条件は、AIが単位・総量・1日量へ構造化し、ユーザーが学習項目候補とともに確認・修正する。システムは確認済みの構造化値から必要日数を決定的に計算し、解釈できない条件が残る場合はWBS下書き生成を開始しない。 |
