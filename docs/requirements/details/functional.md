# 機能要件

## 9. 機能要件

### 9.1 ユーザー管理

| ID | 要件 |
| --- | --- |
| USR-01 | ユーザーはメールアドレスとパスワードでアカウントを登録できる。 |
| USR-02 | ユーザーは登録済みの認証情報でログインできる。 |
| USR-03 | ユーザーはログアウトできる。 |
| USR-04 | ユーザーは自分が登録したデータのみ閲覧・更新できる。 |
| USR-05 | パスワードは平文で保存しない。 |
| USR-06 | メールアドレスは大文字小文字を区別せず一意とする。 |
| USR-07 | パスワードは8文字以上とし、英大文字、英小文字、数字をそれぞれ1文字以上含める。 |
| USR-08 | 認証に失敗した場合、メールアドレスまたはパスワードのどちらが誤っているかを特定できないメッセージを表示する。 |

### 9.2 学習プロジェクト管理

| ID | 要件 |
| --- | --- |
| PRJ-01 | ユーザーは学習プロジェクトを作成できる。 |
| PRJ-02 | 学習プロジェクトには、名称、概要、開始日、目標終了日を設定できる。 |
| PRJ-03 | ユーザーは学習プロジェクトの内容を編集できる。 |
| PRJ-04 | ユーザーは学習プロジェクトを一覧表示できる。 |
| PRJ-05 | 一覧では、状態、期間、進捗率、予定工数、実績工数を確認できる。 |
| PRJ-06 | ユーザーは学習プロジェクトを未着手、進行中、完了の状態で管理できる。 |
| PRJ-07 | ユーザーは学習プロジェクトの詳細を表示できる。 |
| PRJ-08 | 学習プロジェクトの予定工数、実績工数、進捗率は、所属するリーフタスクから自動集計される。 |
| PRJ-09 | ユーザーは学習プロジェクトをアーカイブし、通常の一覧から除外できる。 |
| PRJ-10 | ユーザーはアーカイブ済みプロジェクトを復元できる。 |
| PRJ-11 | アーカイブ済みプロジェクトは閲覧のみ可能とし、編集する場合は復元を必要とする。 |
| PRJ-12 | 最終MVPでは学習プロジェクトの物理削除機能を提供しない。 |
| PRJ-13 | システムはプロジェクト開始日と目標終了日の変更履歴を保存する。 |
| PRJ-14 | 学習プロジェクト作成時、名称、開始日、目標終了日は必須とする。 |
| PRJ-15 | 学習プロジェクト作成時の初期状態は未着手とする。 |
| PRJ-16 | ユーザーはプロジェクト一覧をキーワード、状態、アーカイブ有無で絞り込める。 |
| PRJ-17 | ユーザーはプロジェクト一覧を更新日時、開始日、目標終了日、進捗率で並び替えできる。 |
| PRJ-18 | プロジェクト詳細では、プロジェクト基本情報、主要指標、WBS概要、関連質問、進捗可視化を確認できる。 |
| PRJ-19 | ユーザーはプロジェクト詳細を起点に、WBS編集、質問登録、AI学習計画修正へ移動できる。 |
| PRJ-20 | ユーザーはプロジェクト状態を未着手、進行中、完了の範囲で変更できる。 |
| PRJ-21 | 完了条件を満たさないプロジェクトを完了に変更しようとした場合、システムは変更を拒否し、未完了リーフタスクの存在を表示する。 |
| PRJ-22 | プロジェクト開始日または目標終了日を変更した場合、システムは変更後の期間に基づいて計画情報の整合性を再判定する。 |
| PRJ-23 | プロジェクトをアーカイブした場合、通常のプロジェクト一覧、ダッシュボード、予定タスクの初期表示から除外する。 |
| PRJ-24 | アーカイブ済みプロジェクトを復元した場合、通常の一覧、ダッシュボード、予定タスクの表示対象に戻す。 |
| PRJ-25 | ユーザーはアーカイブ済みプロジェクトも明示的な絞り込みにより一覧表示できる。 |
| PRJ-26 | システムはプロジェクトの作成日時、更新日時、アーカイブ日時、復元日時を保持する。 |
| PRJ-27 | プロジェクト詳細では、WBSタスクが未登録の場合にWBS作成またはAI学習計画生成へ進む導線を表示する。 |
| PRJ-28 | プロジェクト詳細では、プロジェクトの学習状況を判断する主要情報を初期表示で確認できる。 |

### 9.3 WBS管理

| ID | 要件 |
| --- | --- |
| WBS-01 | ユーザーは学習プロジェクト内にWBSタスクを作成できる。 |
| WBS-02 | WBSタスクには、名称、説明、親タスクを設定できる。 |
| WBS-03 | リーフタスクには、開始予定日、終了予定日、予定工数、進捗率を設定できる。 |
| WBS-04 | ユーザーはWBSタスクを最大5階層で管理できる。 |
| WBS-05 | ユーザーはWBSタスクを編集できる。 |
| WBS-06 | ユーザーは同じ親タスク配下のWBSタスクを上下移動できる。 |
| WBS-07 | ユーザーはインデント・アウトデント操作によりWBSタスクの階層を変更できる。 |
| WBS-08 | ユーザーは関連データが存在しないWBSタスクを削除できる。 |
| WBS-09 | ユーザーはリーフタスクの進捗率を0%から100%まで10%単位で更新できる。 |
| WBS-10 | 進捗率が100%になったリーフタスクは完了状態として扱う。 |
| WBS-11 | 完了状態を解除する場合、進捗率を100%未満へ変更できる。 |
| WBS-12 | ユーザーはリーフタスクに対して実績工数を記録できる。 |
| WBS-13 | 親タスクの予定日、予定工数、実績工数、進捗率は配下リーフタスクから自動集計される。 |
| WBS-14 | ユーザーはタスクの遅延状態を確認できる。 |
| WBS-15 | システムはリーフタスク作成時に0%の進捗履歴を保存し、進捗率が変更されるたびに変更後の値を履歴として保存する。 |
| WBS-16 | システムは開始予定日、終了予定日、予定工数、親子関係の変更履歴を保存する。 |

### 9.4 実績時間・学習メモ管理

| ID | 要件 |
| --- | --- |
| LOG-01 | ユーザーはリーフタスクに対して実績時間を記録できる。 |
| LOG-02 | 実績時間は0以上の値とし、0.25時間単位で入力できる。 |
| LOG-03 | 実績時間の変更に応じて、タスクとプロジェクトの実績工数が再集計される。 |
| LOG-04 | ユーザーは完了済みリーフタスクにも実績時間を記録できる。 |
| LOG-05 | ユーザーは必要に応じてリーフタスクに学習メモを追加できる。 |
| LOG-06 | ユーザーは追加した学習メモを確認できる。 |

### 9.5 進捗・EVM管理

| ID | 要件 |
| --- | --- |
| EVM-01 | システムはプロジェクト単位でBAC、PV、EV、ACを計算する。 |
| EVM-02 | システムはプロジェクト単位でSV、CV、SPI、CPIを計算する。 |
| EVM-03 | ユーザーは基準日を指定してEVM指標を確認できる。 |
| EVM-04 | ユーザーはEVM指標をグラフで確認できる。 |
| EVM-05 | システムは工数超過、進捗遅延、指標未算出を区別して表示する。 |
| EVM-06 | システムはプロジェクト単位で理想線と実績線を含むバーンダウンチャートを表示する。 |
| EVM-07 | バーンダウンチャートは日ごとの残予定工数を表示する。 |
| EVM-08 | 将来日付のPVは、タスクの予定期間に基づいて算出できる。 |
| EVM-09 | 過去の基準日におけるBAC、PV、EVは、基準日時点の計画履歴と進捗履歴に基づいて算出する。 |
| EVM-10 | 過去のバーンダウン理想線は、基準日時点のプロジェクト期間に基づいて表示する。 |
| EVM-11 | 計画情報に不整合が存在する場合、計画不整合として警告する。 |
| EVM-12 | システムはバーンダウンチャートにおいて、基準日時点の前倒し、予定どおり、遅れ、算出不可を区別して表示する。 |

### 9.6 質問管理

| ID | 要件 |
| --- | --- |
| QST-01 | ユーザーは質問を登録できる。 |
| QST-02 | 質問には、タイトル、質問内容、関連プロジェクト、関連WBSタスク、カテゴリ、状態を設定できる。 |
| QST-03 | 関連プロジェクトは必須、関連WBSタスクは任意とする。 |
| QST-04 | 質問の状態は、未解決、調査中、解決済みで管理できる。 |
| QST-05 | ユーザーは質問に回答メモを保存できる。 |
| QST-06 | ユーザーは質問と回答メモを編集できる。 |
| QST-07 | ユーザーは質問を削除できる。 |
| QST-08 | ユーザーはキーワード、状態、カテゴリ、プロジェクトで質問を検索・絞り込みできる。 |
| QST-09 | 解決済みに変更する場合、ユーザー入力の回答メモを必須とする。 |
| QST-10 | ユーザーは回答メモとAI回答履歴を保持したまま、解決済みの質問を未解決または調査中へ戻せる。 |
| QST-11 | 質問を削除する場合、確認後に回答メモとAI回答履歴も物理削除する。 |

### 9.7 AI回答

| ID | 要件 |
| --- | --- |
| AI-01 | ユーザーは登録した質問に対するAI回答を生成できる。 |
| AI-02 | システムは生成に成功したAI回答を質問に関連付けて保存する。 |
| AI-03 | ユーザーはAI回答とユーザー入力の回答メモを区別して確認できる。 |
| AI-04 | ユーザーはAI回答を再生成でき、質問を削除するまで過去の成功回答をすべて確認できる。 |
| AI-05 | システムはAI回答生成中の同一質問に対する二重実行を防止する。 |
| AI-06 | AI回答の生成に失敗した場合、質問、回答メモ、既存のAI回答を失わずに失敗理由を表示し、再試行できる。 |
| AI-07 | ユーザーはAI回答機能の初回利用時に、外部AIサービスへの情報送信に同意する。 |
| AI-08 | AI回答生成時に送信できる情報は、質問情報、関連タスク情報、ユーザーが選択した学習メモと回答メモとする。 |
| AI-09 | ユーザーが選択できる学習メモと回答メモは合計10件までとする。 |
| AI-10 | AIサービスへユーザーの認証情報を送信しない。 |

### 9.8 AI学習計画生成

| ID | 要件 |
| --- | --- |
| PLN-01 | AI学習計画生成の入力は、目次テキストと教材目次画像とする。 |
| PLN-02 | PC Webでは、チャット型入力欄から目次テキストの入力、教材目次画像の添付を利用できる。 |
| PLN-03 | 教材目次画像のOCR処理はサーバー側で扱い、将来のFlutterスマホアプリから送信される画像にも再利用できるようにする。 |
| PLN-04 | ユーザーはOCR結果または貼り付けた目次テキストをAI送信前に確認・修正できる。 |
| PLN-05 | ユーザーはチャット型入力欄で、学習目的、期限、学習可能時間、制約条件を自然文で依頼してAI学習計画案を生成できる。 |
| PLN-06 | AI学習計画案には、学習プロジェクト候補、WBS候補、予定日、予定工数を含める。 |
| PLN-07 | AI学習計画案は直接保存せず、ユーザーが確認してからプロジェクトとWBSとして保存する。 |
| PLN-08 | AI学習計画生成に失敗した場合、入力済みの教材名、OCR結果、生成条件を失わず、失敗理由を表示し、再試行できる。 |
| PLN-09 | AI学習計画生成時に、ユーザーの認証情報をAIサービスへ送信しない。 |
| PLN-10 | AI学習計画生成中は実行停止操作を表示し、生成中の二重実行を防止する。 |
| PLN-11 | 教材目次画像は複数アップロードできる。 |
| PLN-12 | 対応画像形式はjpg、jpeg、png、webpとする。 |
| PLN-13 | 教材目次画像は最大10枚、1画像あたり最大10MB、合計最大50MBまでとする。 |
| PLN-14 | 複数画像のOCR結果は、ユーザーが指定した画像順に結合する。 |
| PLN-15 | ユーザーはアップロードした教材目次画像の並び順を変更できる。 |
| PLN-16 | ユーザーはAI学習計画案の作成後、チャットで追加依頼を行い、WBS、予定日、予定工数の修正案を生成できる。 |
| PLN-17 | 保存済みプロジェクトでも、ユーザーはチャットで「この日は勉強できない」「期限を1週間延ばす」などの計画修正を依頼できる。 |
| PLN-18 | AIによる計画修正案は直接反映せず、変更差分をユーザーが確認して承認した場合だけプロジェクトとWBSへ反映する。 |
| PLN-19 | AIによる計画修正案も、WBS階層、予定工数、予定日、進捗履歴、計画履歴の既存ルールに従う。 |
| PLN-20 | ユーザーはAI学習計画生成時に、重点的に学習したい範囲、軽く確認したい範囲、除外したい範囲を自然文で指定できる。 |
| PLN-21 | ユーザーは複数の教材、問題集、公式ドキュメントの目次やメモを1つのAI学習計画生成依頼に含められる。 |

### 9.9 ダッシュボード

| ID | 要件 |
| --- | --- |
| DSH-01 | ユーザーは進行中の学習プロジェクトを確認できる。 |
| DSH-02 | ユーザーはプロジェクトごとの進捗率、予定工数、実績工数、目標終了日を確認できる。 |
| DSH-03 | ユーザーは遅延しているWBSタスクを確認できる。 |
| DSH-04 | ユーザーは今後の予定タスクと未解決質問を確認できる。 |
| DSH-05 | ユーザーは未解決または調査中の質問数と質問一覧を確認できる。 |
| DSH-06 | ユーザーは今日から今後7日以内に予定されている未完了リーフタスクを確認できる。 |
