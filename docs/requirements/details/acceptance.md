# 受入条件・制約・次工程

## 18. 受入条件

### 18.1 MVP 1

MVP 1は、個人用の学習計画・実績管理表として、プロジェクト、WBS、実績時間を登録し、予定工数、実績工数、進捗率を確認できる状態を完成条件とする。

1. ユーザーがアカウント登録、ログイン、ログアウトを行い、自分のデータだけを閲覧・更新できる。
2. ユーザーが学習プロジェクトを作成、編集、一覧表示、詳細表示、アーカイブ、復元できる。
3. ユーザーがプロジェクト内に親タスクとタスクを作成し、タスクを親タスク配下または親なしで管理できる。
4. ユーザーがタスクに予定日、予定工数、実績工数、進捗率を設定できる。
5. 親タスクを除くタスクから、プロジェクトの予定工数、実績工数、進捗率が正しく集計される。
6. 親タスクは予定日、予定工数、実績工数、進捗率、学習メモを持たず、計算対象外として扱われる。
7. 文字数、工数、進捗率、日付、所有者、アーカイブ状態の制約を満たさない操作は保存されず、理由が表示される。

### 18.1.1 プロジェクト管理

1. ユーザーが必須項目を入力してプロジェクトを作成すると、初期状態が未着手で保存される。
2. ユーザーがプロジェクト名、概要、開始日、目標終了日、状態を編集できる。
3. プロジェクト開始日が目標終了日より後の場合、保存できない。
4. タスクが存在しない、または未完了タスクが存在するプロジェクトは完了に変更できない。
5. ユーザーがキーワード、状態、アーカイブ有無でプロジェクト一覧を絞り込める。
6. ユーザーが更新日時、開始日、目標終了日、進捗率でプロジェクト一覧を並び替えできる。
7. プロジェクトをアーカイブすると、通常の一覧、ダッシュボード、予定タスクの初期表示から除外される。
8. アーカイブ済みプロジェクトを復元すると、アーカイブ前の状態を保持したまま通常表示に戻る。
9. アーカイブ済みプロジェクトでは、プロジェクト、WBS、実績時間、学習メモを更新できない。
10. プロジェクト詳細では、主要指標とWBS概要を確認でき、後続MVPで追加する進捗分析、質問、AI支援の配置方針を確認できる。

### 18.2 MVP 2

1. タスク作成時と進捗変更時に進捗履歴が保存される。
2. 予定日、予定工数、階層、プロジェクト期間の変更履歴が保存される。
3. プロジェクト詳細でBAC、PV、EV、AC、SV、CV、SPI、CPIを確認できる。
4. 過去の基準日におけるEVM指標が、当時の計画履歴と進捗履歴に基づいて再現される。
5. プロジェクト詳細で理想線と実績線を含むバーンダウンチャートを確認できる。
6. 遅延タスクと計画上の不整合を確認できる。

### 18.3 MVP 3

1. ユーザーが質問と回答メモを登録、編集、検索できる。
2. 回答メモがない質問を解決済みに変更できない。
3. 解決済みの質問を回答メモを保持したまま再オープンできる。
4. 質問を削除する場合、確認後に回答メモとAI回答履歴も削除される。
5. ユーザーがAI回答機能の初回利用時に外部送信へ同意できる。
6. ユーザーが送信する学習メモと回答メモを合計10件まで選択できる。
7. ユーザーが登録した質問に対するAI回答を生成・保存できる。
8. ユーザーがAI回答と回答メモを区別して確認できる。
9. ユーザーがAI回答を再生成し、過去の成功回答を確認できる。
10. AI回答生成に失敗した場合、質問、回答メモ、既存AI回答が失われず、再試行できる。

### 18.4 MVP 4

1. ユーザーが教材目次画像または目次テキストからOCR結果を確認・修正できる。
2. ユーザーが修正済み目次と自然文の依頼内容をもとにAI学習計画案を生成できる。
3. ユーザーがAI学習計画案のWBS、予定日、予定工数を保存前に確認できる。
4. ユーザーがAI学習計画案を確認して承認した場合だけ、プロジェクトとWBSとして保存される。
5. AI学習計画生成に失敗した場合、教材名、OCR結果、自然文の依頼内容が失われず、再試行できる。
6. ユーザーがチャットでAI学習計画案または保存済み計画の修正を依頼できる。
7. AI修正案は、ユーザーが変更差分を確認して承認した場合だけ反映される。

## 19. 制約・前提事項

- 初期リリースは個人開発として、段階リリースにより完成を優先する。
- 日本語UIを主対象とする。
- Flutterスマホアプリは別リポジトリで作成し、将来的にPC Web版と同じ主要機能を提供する。
- タイムゾーンはユーザー設定を導入するまで日本標準時（JST）を基準とする。
- 日付は日単位で管理し、最終MVPではタスクの開始時刻・終了時刻を管理しない。
- EVMは学習時間をコストとして扱うため、一般的な金額ベースのEVMとは表示上の意味が異なる。
- PVは休日を除外せず、全暦日へ均等配分する。
- AI回答は誤りを含む可能性があるため、参考情報として表示し、ユーザーが回答メモで検証結果を残せるようにする。

7. EVM、タスク集計、履歴再現などの業務ロジックを設計する。
8. 技術スタック、開発環境、テスト方針、実装順序を決定する。
