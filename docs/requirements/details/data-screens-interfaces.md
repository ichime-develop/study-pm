# データ・画面・外部インターフェース

## 15. データ要件

最終MVPで管理する主要データは以下とする。詳細な項目、型、制約、関連はDB設計で定義する。

| データ | 主な内容 |
| --- | --- |
| ユーザー | 認証情報、表示名、AI利用同意 |
| 学習プロジェクト | 名称、概要、分野、期間、状態、アーカイブ情報、作成日時、更新日時 |
| プロジェクト期間履歴 | 変更前後の開始日、変更前後の目標終了日、変更日時 |
| WBSタスク | 階層、予定日、予定工数、進捗率、表示順 |
| WBS計画履歴 | 予定日、予定工数、親子関係、変更日時 |
| WBS進捗履歴 | 進捗率、変更日時、対象タスク |
| 学習記録 | 学習日、学習時間、メモ、対象タスク |
| 質問 | 質問内容、カテゴリ、状態、関連プロジェクト・タスク |
| 回答メモ | ユーザーが入力した回答内容 |
| AI回答 | AIが生成した回答内容、生成日時、生成結果 |
| AI送信情報 | AI回答生成時にユーザーが選択した関連情報 |
| AI学習計画入力 | 教材名、OCR結果、貼り付け目次テキスト、自然文の依頼内容 |
| AI学習計画案 | AIが生成したWBS候補、予定日、予定工数、生成結果 |
| AI計画修正案 | AIが生成したWBS、予定日、予定工数の変更差分 |

### 15.1 データ保持方針

- 作成日時、更新日時を主要データに保持する。
- ユーザー所有データには所有者を特定できる情報を保持する。
- プロジェクトはアーカイブによる非表示を基本とし、物理削除しない。
- WBSタスクは関連データが存在しない場合だけ物理削除できる。
- 質問は確認後、回答メモとAI回答履歴を含めて物理削除できる。
- 学習記録の変更後は、実績工数の集計結果との整合性を保つ。
- 過去時点のEVMとバーンダウンを再現するため、計画履歴と進捗履歴を保持する。
- 外部サービス固有の情報を主要業務データへ直接埋め込みすぎない。

## 16. 画面要件一覧

詳細なレイアウト、遷移、入力項目は画面設計で定義する。

画面モックはMVP 1だけに閉じず、最終MVP全体の機能配置を見据えて作成する。特にプロジェクト詳細画面は、WBS、学習記録、進捗分析、質問、AI支援が密接に関わる中心画面として扱う。

ただし、各MVPで実装する画面機能は段階リリースに従って切り分ける。MVP 1では、個人用の学習計画・実績管理表として必要なプロジェクト、WBS、学習記録、基本ダッシュボード、認証を実装対象とし、EVM、バーンダウン、質問、AI支援は画面構造上の配置を考慮するが実装対象外とする。

| --- | --- | --- |
| SCR-01 | アカウント登録画面 | 新規ユーザー登録 |
| SCR-02 | ログイン画面 | ログイン |
| SCR-03 | ダッシュボード画面 | 学習状況の概要確認 |
| SCR-04 | プロジェクト一覧画面 | プロジェクト検索・一覧表示、アーカイブ表示 |
| SCR-05 | プロジェクト作成・編集画面 | プロジェクト情報の入力 |
| SCR-06 | プロジェクト詳細画面 | プロジェクト状況、WBS、進捗、EVM、バーンダウン、関連情報の確認 |
| SCR-07 | WBS編集画面 | WBSタスクの作成・編集・上下移動・階層変更 |
| SCR-08 | 学習記録一覧画面 | 学習記録の検索・一覧表示 |
| SCR-09 | 学習記録登録・編集画面 | 学習実績の入力 |
| SCR-10 | 質問一覧画面 | 質問の検索・一覧表示 |
| SCR-11 | 質問登録・編集画面 | 質問、AI回答、回答メモの入力・確認 |

| SCR-14 | AI計画作成: 計画チャット画面 | 生成済み計画への自然文追加依頼、修正案、変更差分の確認 |
| SCR-15 | AI計画作成: 生成結果確認画面 | AIが作成したWBSと学習計画の確認・保存 |

### 16.1 プロジェクト詳細画面

プロジェクト詳細画面は、ユーザーが学習プロジェクトの状況を日常的に確認し、次の行動を判断する中心画面とする。

| ID | 要件 |
| --- | --- |
| SCR-06-01 | ユーザーはプロジェクト名、概要、学習分野、状態、開始日、目標終了日、アーカイブ状態を確認できる。 |
| SCR-06-02 | ユーザーはプロジェクトの予定工数、実績工数、残予定工数、進捗率を画面上部で確認できる。 |
| SCR-06-03 | ユーザーは進捗遅延、工数超過、計画不整合、未解決質問の有無を画面上部で区別して確認できる。 |
| SCR-06-04 | ユーザーはプロジェクト編集、状態変更、アーカイブ、復元、WBS編集、学習記録登録、質問登録へ遷移できる。 |
| SCR-06-05 | アーカイブ済みプロジェクトの場合、画面は閲覧専用とし、編集系操作の代わりに復元操作を表示する。 |
| SCR-06-06 | ユーザーは基準日を指定し、指定した基準日に基づく進捗、遅延、EVM、バーンダウンを確認できる。 |
| SCR-06-07 | 基準日の初期値はJSTの当日とする。 |
| SCR-06-08 | ユーザーはWBSを階層構造で確認できる。 |
| SCR-06-09 | WBS表示では、タスク名、階層、予定日、予定工数、実績工数、進捗率、遅延状態、計画不整合を確認できる。 |
| SCR-06-10 | ユーザーはWBS上でリーフタスクと親タスクを区別して確認できる。 |
| SCR-06-11 | ユーザーは未完了のリーフタスクを予定日、遅延状態、進捗率で把握できる。 |
| SCR-06-12 | ユーザーはプロジェクト詳細からリーフタスクの進捗率更新へ移動できる。 |
| SCR-06-13 | ユーザーはプロジェクト詳細から対象リーフタスクを指定して学習記録登録へ移動できる。 |
| SCR-06-14 | ユーザーはBAC、PV、EV、AC、SV、CV、SPI、CPIを同一画面内で確認できる。 |
| SCR-06-15 | EVM指標が算出不可の場合、対象指標を「算出不可」と表示し、工数超過や進捗遅延とは区別する。 |
| SCR-06-16 | ユーザーはEVM指標の推移をグラフで確認できる。 |
| SCR-06-17 | ユーザーは理想線と実績線を含むバーンダウンチャートを確認できる。 |
| SCR-06-18 | バーンダウンチャートでは、プロジェクト期間外タスクが存在する場合に計画不整合を表示する。 |
| SCR-06-19 | ユーザーはプロジェクトに関連する直近の学習記録を確認できる。 |
| SCR-06-20 | ユーザーはプロジェクトに関連する未解決または調査中の質問を確認できる。 |
| SCR-06-21 | WBSタスクが未登録の場合、WBS作成またはAI学習計画生成へ進める導線を表示する。 |
| SCR-06-22 | 学習記録が未登録の場合、学習記録登録へ進める導線を表示する。 |
| SCR-06-23 | 画面上部の主要指標は、WBS、EVM、バーンダウン、学習記録、質問の詳細領域へ移動しなくても確認できる。 |

## 17. 外部インターフェース要件

### 17.1 最終MVP

- バックエンドはPC Webから利用するREST APIを提供する。
- REST APIは、将来のFlutterスマホアプリからも利用できるように入出力仕様を整理する。
- APIの入出力はJSONを基本とする。
- AI APIを利用して、登録した質問に対する回答を生成する。
- AI APIを利用して、教材目次画像のOCR、WBS候補、学習計画案を生成する。
- AI APIの認証情報はサーバー側で管理し、PC Webへ公開しない。
- AI APIへ送信する情報は、質問情報、関連タスク情報、ユーザーが選択した学習記録と回答メモに限定する。
- AI学習計画生成時にAI APIへ送信する情報は、ユーザーが修正したOCR結果または貼り付け目次テキスト、教材名、自然文の依頼内容に限定する。
