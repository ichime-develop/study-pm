# データ・画面・外部インターフェース

## 15. データ要件

最終MVPで管理する主要データは以下とする。詳細な項目、型、制約、関連はDB設計で定義する。

| データ | 主な内容 |
| --- | --- |
| ユーザー | 認証情報、表示名 |
| 学習プロジェクト | 名称、概要、期間、状態、作成日時、更新日時 |
| プロジェクト期間履歴 | 変更前後の開始日、変更前後の目標終了日、変更日時 |
| WBSタスク | 種別、親タスク、予定日、予定工数、進捗率、表示順 |
| WBS計画履歴 | 予定日、予定工数、親タスク、変更日時 |
| WBS進捗履歴 | 進捗率、変更日時、対象タスク |
| 学習記録 | 学習日、対象タスク、学習時間、任意メモ |
| AI学習計画入力 | 学習目標、学習開始日、目標終了日、複数の入力元（概要、教材名、修正済みOCR、貼り付け目次）、こだわり条件（平日・土日の学習可能時間、学習できない曜日、日程補足、重点範囲等）、ユーザー入力の数量条件とWBS分割単位 |
| AI処理ジョブ | WBS生成の状態、受付日時、期限、再試行回数、失敗理由、使用したモデル・プロンプト・スキーマ・生成戦略の版 |
| WBS下書き | AIが生成しサーバー検証を通過した親タスク・タスク、予定日、予定工数、警告、入力元との対応、変換状態 |

### 15.1 データ保持方針

- 作成日時、更新日時を主要データに保持する。
- ユーザー所有データには所有者を特定できる情報を保持する。
- 不要なプロジェクトは削除できる。削除前に確認し、削除後は復元できない。
- タスクは学習記録が存在しない場合だけ物理削除できる。親タスク削除時は、削除前確認後に配下タスクも削除対象とする。
- 学習記録が存在するタスクも同一プロジェクト内での編集は可能とし、別プロジェクトへ移動できない。
- 学習記録の追加、変更、削除後は、実績工数の集計結果との整合性を保つ。
- 学習記録は、タスク、プロジェクト、ユーザー単位の集計に利用できるように、対象タスク、所属プロジェクト、所有ユーザーを特定できる情報を保持する。
- 進捗履歴、WBS計画履歴、プロジェクト期間履歴を保持する。
- 進捗履歴は、JSTの各日終了時点における日別EVとバーンダウン実績線の算出に利用する。
- WBS計画履歴およびプロジェクト期間履歴は、MVP 2のEVM・バーンダウン計算には使用せず、将来拡張または変更追跡のために保持する。
- 履歴一覧をユーザーへ表示する機能は提供しない。
- 外部サービス固有の情報を主要業務データへ直接埋め込みすぎない。
- 教材目次画像はOCR処理中の一時データとして扱い、永続保存しない。
- OCR結果、修正後テキスト、生成条件、WBS下書きと入力元対応は、再開、再試行、保存前確認、生成品質評価に必要な設定期間だけ保持し、期限到達後に自動削除する。
- 入力元とWBS下書きタスクの対応は、生成品質評価に利用する。
- プロジェクトへの変換後は、入力元との対応をプロジェクト・WBSへ引き継がない。
- WBS下書きは1回だけプロジェクトへ変換できる状態を保持する。

## 16. 画面要件一覧

詳細なレイアウト、遷移、入力項目は画面設計で定義する。

画面モックはMVP 1だけに閉じず、最終MVP全体の機能配置を見据えて作成する。プロジェクト選択後の作業スペースは、概要、WBS、学習記録、進捗分析が密接に関わる中心領域として扱う。AI学習計画生成は、新規プロジェクト作成時の独立した作成ルートとして扱う。

ただし、各MVPで実装する画面機能は段階リリースに従って切り分ける。MVP 1では、個人用の学習計画・実績管理表として必要なプロジェクト、WBS、学習記録、プロジェクト一覧ホーム、認証を実装対象とし、EVM、バーンダウン、AI学習計画生成は画面構造上の配置を考慮するが実装対象外とする。

ナビゲーションは、プロジェクト未選択時とプロジェクト選択後で表示対象を切り替える。プロジェクト未選択時はプロジェクト一覧、プロジェクト作成、AI学習計画生成などの共通機能を中心に表示し、プロジェクト選択後は選択中プロジェクトの概要、WBS、進捗分析、学習記録などのプロジェクト内機能を中心に表示する。
具体的なサイドバー、タブ、パンくず、戻る導線の配置は基本設計で決定する。

| 画面ID | 画面名 | 主な用途 |
| --- | --- | --- |
| AU01 | アカウント登録画面 | 新規ユーザー登録 |
| AU02 | ログイン画面 | ログイン |
| PJ01 | プロジェクト一覧画面 | ログイン後のホーム、プロジェクト検索・一覧表示、ユーザー単位の学習サマリー確認 |
| PJ02 | プロジェクト作成・編集画面 | プロジェクト情報の入力 |
| PJ03 | プロジェクト概要画面 | 選択中プロジェクトの概要、主要指標、警告、未完了タスクの確認 |
| AN01 | プロジェクト内進捗分析 | EVM、バーンダウン、計画との差の確認 |
| SL01 | プロジェクト内学習記録 | プロジェクト内の学習記録一覧、登録、編集、削除 |
| WB01 | WBS編集領域 | 親タスク・タスクの作成・編集・自動並び替え・親タスク設定 |

### 16.5 WBS編集領域

WBS編集領域（WB01）では、プロジェクト内の親タスクとタスクを作成・編集し、ガントチャートで期間を確認する。WBSタスクが0件の状態でも画面を表示し、作成を開始できる。

| ID | 要件 |
| --- | --- |
| SCR.WB01-01 | WBSタスクが0件の場合でも、WBS・ガント画面を表示し、親タスクまたは親なしタスクの追加を開始できる。 |
| SCR.WB01-02 | WBSが空の場合、「親タスクを追加する」「親なしタスクを追加する」の操作を開始できる。 |
| SCR.WB01-03 | 親タスクは名称と任意の説明を登録する見出しとし、予定日、予定工数、進捗率を持たない。 |
| SCR.WB01-04 | タスクは名称（必須）、説明（任意）、親タスク（任意）、予定開始日（任意）、予定終了日（任意）、予定工数（必須）を入力して登録する。 |

## 17. 外部インターフェース要件

### 17.1 最終MVP

- バックエンドはPC Webから利用するREST APIを提供する。
- REST APIは、将来のFlutterスマホアプリからも利用できるように入出力仕様を整理する。
- APIの入出力はJSONを基本とする。
- Google Cloud Visionの文書向けテキスト検出を利用して教材目次画像からテキストを抽出し、OpenAI APIを利用してWBS下書きを生成する。
- AI APIの認証情報はサーバー側で管理し、PC Webへ公開しない。
- Google Cloud Visionへは教材目次画像だけを送信し、OpenAIへ画像を送信しない。
- WBS下書き生成時にOpenAIへ送信する情報は、学習目標、学習内容の概要、ユーザーが修正したOCR結果または貼り付け目次テキスト、こだわり条件に限定する。入力済み数量条件がある場合はその値を正本とする。
- 認証情報、メールアドレス、表示名、内部UUID、学習記録、他プロジェクトの情報を外部OCR・AIサービスへ送信しない。
