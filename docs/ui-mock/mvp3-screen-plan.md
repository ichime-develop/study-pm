# MVP3 AI学習計画作成 画面計画

## 1. 目的

AIの不確定な出力をそのまま保存せず、入力、学習項目候補、WBS下書きをユーザーが段階的に確認できるPC Web UIを定義する。

本書はUIモックを更新する前の設計正本である。既存の `mock/` はAI01〜AI03の3画面構成のため、本設計のAI01〜AI04とは一致していない。このブランチではモック実装を変更せず、別タスクで同期する。

## 2. 画面構成

| ステップ | 画面 | ユーザーが確認すること | 次へ進む条件 |
| --- | --- | --- | --- |
| 1 | AI01 作成方法選択 | 作成方法、外部サービス、送信範囲 | 概要または目次を選択 |
| 2 | AI02 条件・教材入力 | 学習条件、画像、OCR結果、文字数、入力矛盾 | 入力検証に成功し、候補抽出が完了 |
| 3 | AI03 学習項目候補確認 | 学ぶ範囲、由来、重点・通常・軽め・除外 | 現在の候補一覧を一括確認 |
| 4 | AI04 WBS下書き確認 | WBS階層、日程、工数、警告、変更案 | 下書き再検証に成功 |

CM03ステッパーは4ステップを表示する。戻る操作では入力と確認対象を保持するが、候補や条件の変更により後続成果物が古くなった場合は再確認・再生成を要求する。

AI02で入力を保存した後は生成依頼ID、AI04では下書きIDをURLへ含める。画面再読み込み時はサーバーから現在状態を取得し、処理中ならポーリングを再開する。

## 3. AI01 作成方法選択

### 3.1 レイアウト

- 画面上部に「AIと学習計画を作成」と4ステップのステッパーを表示する。
- 「概要から作成」「目次から作成」を同じ強さの選択カードとして表示する。
- 選択カードの下に外部サービス利用の注意書きを常時表示する。モーダルや折りたたみ内へ隠さない。

### 3.2 注意書き

次を短い見出しと箇条書きで表示する。

- 教材目次画像はGoogle Cloud Visionへ送信する。
- OpenAIへは修正済みテキスト、確認済み学習項目候補、生成条件を送信する。
- OpenAIへ画像、認証情報、学習記録、他プロジェクトの情報を送信しない。
- 各サービスのデータ利用方針へのリンク。
- 「次へ」を押すと、この内容を確認したものとして進む。

専用チェックボックスや同意履歴画面は設けない。

## 4. AI02 条件・教材入力

### 4.1 情報のまとまり

1. 学習目標と期間
2. 学習内容
3. 教材画像・OCR
4. こだわり条件
5. 入力確認と候補抽出

PC画面でも縦長になるため、こだわり条件だけは任意項目として折りたためる。学習目標、期間、学習内容、OCR結果は折りたたまない。

### 4.2 画像とOCR

- 最大10枚のサムネイルを横並びまたはグリッドで表示する。
- 選択中の画像枚数と合計サイズを表示し、10枚または50MBを超えた場合はOCR送信前に修正方法を表示する。
- ドラッグ操作に加えて、キーボードでも順序を変更できる。
- 各画像に待機中、処理中、完了、失敗を表示する。
- 失敗画像には画像単位の再試行を表示し、成功画像を再処理しない。
- OCR結果は画像順で結合し、1つの編集可能テキスト領域として表示する。
- 画像を削除・並び替えた場合、OCR結合結果への影響を確認できるようにする。

### 4.3 文字数

- 概要、OCR・目次、こだわり条件の現在文字数と上限を項目付近に表示する。
- 上限超過時は対象項目をエラー表示し、候補抽出ボタンを無効にする。
- 自動切り捨てや、末尾だけが失われるUIにしない。

### 4.4 非同期状態

候補抽出開始後はページ全体を操作不能にせず、入力内容を閲覧できる。主要操作領域に状態、経過中表示、停止ボタンを置く。停止要求中は連打できないようにし、「外部サービスの処理はすぐに止まらない場合があります」と短く表示する。

## 5. AI03 学習項目候補確認

### 5.1 候補一覧

候補を1行1項目で表示する。

| 列・要素 | 内容 |
| --- | --- |
| 学習項目 | 名称と説明。編集可能 |
| 由来 | 入力由来 / AI補足 |
| 優先度 | 重点 / 通常 / 軽め / 除外 |
| 入力元 | 教材名や画像順。入力由来の場合に確認可能 |
| 操作 | 削除 |

AI補足は警告色ではなく、情報バッジで区別する。AI補足であること自体をエラー扱いしない。

### 5.2 確認操作

- 各候補に個別の確認チェックを要求しない。
- 一覧編集後に「候補一覧を確認しました」を1回押す。
- 確認済み状態では確認日時または確認済み表示を出す。
- 候補を変更したら確認済み表示を解除し、「変更したため再確認が必要です」と表示する。
- WBS生成ボタンは、現在版が確認済みで、除外以外が1件以上ある場合だけ有効にする。

### 5.3 数量条件の確認

- 「全300ページを1日10ページ」のような条件をAIが解釈した場合、単位、総量、1日量、根拠文を候補一覧の上に表示する。
- ユーザーは解釈結果を修正でき、変更時は候補一覧と同じく確認済み状態を解除する。
- 解釈できなかった条件は警告として原文と修正方法を表示し、解消するまでWBS生成ボタンを無効にする。
- 期限に収まらない場合は、サーバーが計算した必要日数と利用可能日数を表示し、AIの推測値として見せない。

### 5.4 大量候補

候補が多い場合も全体を確認できるよう、優先度フィルタと名称検索を設ける。フィルタ中の一括操作が全候補か表示中候補かを明記する。候補数の実装上限は評価後に決めるため、本書では固定しない。

## 6. AI04 WBS下書き確認

### 6.1 レイアウト

- WBSを主領域、選択タスク編集を右サイドパネルとする既存WB01の操作感を再利用する。
- 下書きであることを画面タイトルと状態表示で明示する。
- プロジェクト名・期間、警告、変換操作をWBSより上に配置する。
- 下書きタスク名、種別、親、予定日、予定工数を編集できる。
- LEAFタスクを選択したとき、対応する学習項目候補を右サイドパネルの補助情報として表示する。候補名は確認できるが、候補の編集はAI03へ戻って行う。

### 6.2 計画不整合

- 構造エラーと計画警告を分ける。
- 構造エラーがある場合は変換できない。
- 学習可能時間の超過などの計画警告は、警告内容、必要量、解除する条件を表示する。
- 単一条件変更案は最大3件をカードまたはリストで表示する。
- 期限優先を選んだ場合は、希望する1日あたり学習時間を超えることを変換操作の近くで再表示する。

### 6.3 変換

主要ボタンは「この計画でプロジェクトを作成」とする。押下後は再検証中の状態を表示し、二重実行を防止する。成功後は作成したプロジェクトのWBSへ移動する。

## 7. 共通状態

| 状態 | 表示 |
| --- | --- |
| QUEUED | 「処理の開始を待っています」 |
| PROCESSING | 「AIが処理しています」、停止操作 |
| CANCEL_REQUESTED | 「停止を要求しています」、操作無効 |
| COMPLETED | 次画面または結果を表示 |
| FAILED | 失敗理由、保持される入力、対象段階の再試行 |
| CANCELED | 「処理を停止しました」、再試行 |
| 日次上限 | 利用可能になるJST日時 |
| AI機能利用不可 | 手動作成への導線。既存機能は利用可能であることを表示 |

## 8. アクセシビリティ

- 状態を色だけで区別しない。
- 画像並び替え、候補編集、ステッパー、停止操作をキーボードで利用できる。
- 非同期状態は `aria-live` で通知するが、ポーリングごとの更新を読み上げない。
- エラーは対象項目と関連付け、要約だけでなく修正方法を表示する。
- モーダルに依存せず、長い確認内容は画面内に保持する。

## 9. モック同期時の確認項目

- AI01〜AI04の4画面へ分かれていること。
- 6〜10枚の画像と長いOCRテキストでもレイアウトが破綻しないこと。
- 30件以上の候補を編集・一括確認できること。
- 候補変更後に確認済み状態が解除されること。
- WBS下書きの警告と構造エラーを区別できること。
- AI04でLEAFタスクと学習項目候補の対応を確認できること。
- 1280px標準幅でWBSと右サイドパネルを利用できること。
- 停止、失敗、上限到達、外部サービス利用不可の状態を確認できること。
