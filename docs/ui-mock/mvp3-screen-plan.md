# MVP3 AI学習計画作成 画面計画

## 1. 目的

AIの不確定な出力をそのまま保存せず、入力とWBS下書きをユーザーが段階的に確認できるPC Web UIを定義する。

本書はMVP3のAI作成フローにおける画面設計の正本である。`mock/` は本書に基づき、AI01〜AI03の3画面構成へ同期済みである。

## 2. 画面構成

| ステップ | 画面 | ユーザーが確認すること | 次へ進む条件 |
| --- | --- | --- | --- |
| 1 | AI01 作成方法選択 | 作成方法、外部サービス、送信範囲 | 概要または目次を選択 |
| 2 | AI02 条件・教材入力 | 基本条件、こだわり条件、教材・OCR結果、文字数、入力矛盾 | 入力検証に成功し、WBS下書き生成を開始 |
| 3 | AI03 WBS下書き確認 | WBS階層、日程、工数、警告、変更案 | 下書き再検証に成功 |

CM03ステッパーは3ステップを表示する。戻る操作では入力を保持するが、条件・教材を変更した場合は既存の下書きを古いものとして扱い、再生成を要求する。

AI02で入力を保存した後は生成依頼ID、AI03では下書きIDをURLへ含める。画面再読み込み時はサーバーから現在状態を取得し、処理中ならポーリングを再開する。

## 3. AI01 作成方法選択

### 3.1 レイアウト

- 画面上部に「AIと学習計画を作成」と3ステップのステッパーを表示する。
- 「概要から作成」「目次から作成」を選択カードとして表示し、初期状態では「概要から作成」を選択する。
- 選択中のカードは緑系の背景・枠線で明示する。カード選択後、画面右下の「次へ」でAI02へ進む。
- 選択カードの下に外部サービス利用の注意書きを常時表示する。モーダルや折りたたみ内へ隠さない。

### 3.2 注意書き

次を短い見出しと箇条書きで表示する。

- 教材目次画像はGoogle Cloud Visionへ送信する。
- OpenAIへは修正済みテキストと生成条件を送信する。
- OpenAIへ画像、認証情報、学習記録、他プロジェクトの情報を送信しない。
- 各サービスのデータ利用方針へのリンク。
- 「次へ」を押すと、この内容を確認したものとして進む。

専用チェックボックスや同意履歴画面は設けない。

## 4. AI02 条件・教材入力

### 4.1 情報のまとまり

1. 基本条件（学習目標、プロジェクト名、期間）
2. こだわり条件（任意）
3. 学習内容の概要、または教材の目次
4. 入力確認とWBS下書き生成

PC画面でも縦長になるため、こだわり条件だけは任意項目として折りたためる。基本条件と学習内容、OCR結果は折りたたまない。こだわり条件では平日・土日それぞれの学習可能時間、学習できない曜日、日程補足、重点・軽め・除外範囲に加え、学習量の総量、1日あたりの学習量、WBSの分割単位を設定できる。学習できない曜日は曜日別の学習可能時間より優先する。

WBS分割単位は「教材の章・節」を初期値とし、「ページ数」「問題セット」「AIに任せる」を選択できる。「ページ数」を選択する場合は、数量条件の単位をページとし、総量と1日あたりの学習量を入力することを項目付近に表示する。

### 4.2 画像とOCR

- 最大10枚のサムネイルを横並びまたはグリッドで表示する。
- 選択中の画像枚数と合計サイズを表示し、10枚または50MBを超えた場合はOCR送信前に修正方法を表示する。
- ドラッグ操作に加えて、キーボードでも順序を変更できる。
- 各画像に待機中、処理中、完了、失敗を表示する。
- 失敗画像には画像単位の再試行を表示し、成功画像を再処理しない。
- OCR結果は画像順で結合し、1つの編集可能テキスト領域として表示する。
- 画像を削除・並び替えた場合、OCR結合結果への影響を確認できるようにする。

### 4.3 文字数

- 概要、OCR・目次、こだわり条件の現在文字数と上限を項目付近に表示する。
- 上限超過時は対象項目をエラー表示し、WBS下書き生成ボタンを無効にする。
- 自動切り捨てや、末尾だけが失われるUIにしない。

### 4.4 非同期状態

WBS下書き生成開始後はページ全体を操作不能にせず、入力内容を閲覧できる。主要操作領域に状態、経過中表示、停止ボタンを置く。停止要求中は連打できないようにし、「外部サービスの処理はすぐに止まらない場合があります」と短く表示する。

## 5. AI03 WBS下書き確認

### 5.1 レイアウト

- WBSを主領域、選択タスク編集を右サイドパネルとする既存WB01の操作感を再利用する。
- 下書きであることを画面タイトルと状態表示で明示する。
- プロジェクト名・期間、警告、変換操作をWBSより上に配置する。
- 下書きタスク名、種別、親、予定日、予定工数を編集できる。
- AIが教材・概要から読み取った学習範囲は、独立した確認画面ではなく、生成された親タスクとLEAFタスクとして確認する。意図と異なる場合は、タスクを直接編集するか、条件・教材を変更して再生成する。

### 5.2 計画不整合

- 構造エラーと計画警告を分ける。
- 構造エラーがある場合は変換できない。
- 日付ごとの学習可能時間の超過などの計画警告は、警告内容、必要量、解除する条件を表示する。
- 単一条件変更案は最大3件をカードまたはリストで表示する。
- 期限優先を選んだ場合は、希望する1日あたり学習時間を超えることを変換操作の近くで再表示する。

### 5.3 変換

主要ボタンは「この計画でプロジェクトを作成」とする。押下後は再検証中の状態を表示し、二重実行を防止する。成功後は作成したプロジェクトのWBSへ移動する。

## 6. 共通状態

| 状態 | 表示 |
| --- | --- |
| QUEUED | 「処理の開始を待っています」 |
| PROCESSING | 「AIが処理しています」、停止操作 |
| CANCEL_REQUESTED | 「停止を要求しています」、操作無効 |
| COMPLETED | 次画面または結果を表示 |
| FAILED | 失敗理由、保持される入力、対象段階の再試行 |
| CANCELED | 「処理を停止しました」、再試行 |
| 日次上限 | 利用可能になるJST日時 |
| AI機能利用不可 | 手動作成への導線。既存機能は利用可能であることを表示 |

## 7. アクセシビリティ

- 状態を色だけで区別しない。
- 画像並び替え、WBS下書きの編集、ステッパー、停止操作をキーボードで利用できる。
- 非同期状態は `aria-live` で通知するが、ポーリングごとの更新を読み上げない。
- エラーは対象項目と関連付け、要約だけでなく修正方法を表示する。
- モーダルに依存せず、長い確認内容は画面内に保持する。

## 8. モック確認項目

- AI01〜AI03の3画面へ分かれていること。
- 6〜10枚の画像と長いOCRテキストでもレイアウトが破綻しないこと。
- WBS下書きの警告と構造エラーを区別できること。
- 入力した教材・こだわり条件がWBS下書きへ反映され、意図と異なる場合に直接編集または条件・教材の変更を選べること。
- 1280px標準幅でWBSと右サイドパネルを利用できること。
- 停止、失敗、上限到達、外部サービス利用不可の状態を確認できること。
